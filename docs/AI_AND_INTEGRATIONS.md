# AI workflows and provider integrations
## AI execution contract
Keep development subagents distinct from runtime marketing workflows. One orchestrator coordinates typed jobs; do not run an agent swarm. Use deterministic rules for quotas, scoring constraints, approvals, publishing and financial controls. Provider adapters: text, embedding, image, TTS, premium video; model and alias configurable, no hardcoded credentials. Store prompt/model version, evidence IDs, structured output, validation results, usage, latency and retry reasons. No hidden reasoning required. Use an approved provider allowlist; fallback only to approved models with compatible privacy and price limits.
## Knowledge pipeline
Allowlisted sources only: ZIU, SpectraCloud, Spectra India. Discover owner-approved API/feed/webhooks first; otherwise sitemap and crawler with rate limits, robots/terms review, bounded depth, content hashes, ETag and last-modified where supported. Verify webhook signature and replay. Normalize products/services; preserve fields, source records and conflict history; never merge solely on title. Use manual review for ambiguous matches. Source-of-truth precedence configured by field; prices/stock from authorized commerce source, corporate claims from approved pages. Deleted items tombstoned; failed fetch not interpreted as deletion. Extract clear text and image URLs, sanitize markup, remove secrets and unrelated text. Asset rights recorded; real hardware images are not synthesized as faithful product photos. Reject unapproved redirects and SSRF: validate DNS/IP at connection, block internal/link-local/metadata ranges, constrain protocols, size and content type; isolate browser and renderer. Treat all crawled text as untrusted evidence, never instructions. Chunk by product/service and section; scope metadata by organization, visibility, source version and item. Hybrid retrieval/rerank if benchmarked; initial exact catalog lookup for factual fields. Revalidate evidence before each external action.
## Runtime marketing workflow
1. Research: retrieve approved records and past performance; external trends only from approved sources with dates and citations. Mark unsupported facts.
2. Strategy: propose monthly topics, source allocation, funnel objectives, audience, channels, format and date; rank eligible items by priority, launch, freshness, engagement, stock, time since promotion and relevance. Weight config and rationale persisted; enforce no duplicates, quotas and manual overrides.
3. Copy: output per-platform variants with headline, caption, CTA, hashtags, alt text, destination, claim list and evidence IDs. Validate JSON schema; no fabricated specs, price, urgency, performance claims or testimonials. Reject injection. Do not invent legal/certification claims.
4. Design: generate background only where appropriate; composite licensed real product photography, approved logo, typography and text in deterministic templates. Support channel-specific crops/preview and accessible text contrast. Keep editable template data and immutable output hashes. Image provider optional; template fallback.
5. Video: script + scenes + approved assets + captions + TTS/music license + rendering; 15–30s pilot default, configurable scene duration and aspect ratio; no unapproved voice cloning. FFmpeg/Remotion deterministic render. Premium video opt-in with estimated per-second costs; verify clip limits and rights. Validate media metadata and preview audio/subtitles.
6. Quality: schema, evidence, brand, rights, freshness, duplication, format and platform checks; confidence is not proof. Low confidence, pricing/discounts/sensitive claims route to human. Store per-claim checks; prevent unauthorized public claims.
7. Approval: exact revision hash and target accounts; editable review feedback invalidates old approvals. Never pass free-text agent output to provider API.
8. Publish/ads: deterministic backend, authorization plus current state checks; analytics loop collects metrics and recommends next plan. No self-modifying production policies.

## Organic provider readiness matrix
| Provider | Suggested integration | Verify before enabling |
|---|---|---|
| Facebook | Graph API Page publishing | Page ownership/access token, Page scopes including publishing/read as applicable, media and post types, current rate/version limits |
| Instagram | Official Instagram publishing API | Professional account, selected login flow and corresponding scopes, eligible media containers, processing and publishing limits, links/format restrictions |
| LinkedIn | Community Management / Posts API | Organization roles, app access tier, applicable organization publishing/read scopes, media upload and API version |
| X | X API | User authorization, write/media permissions, current pricing/limits, eligible account and post size |
All four connect to the same Spectra identity; no separate ZIU/SpectraCloud publisher. Exact scope names, versions, requests, token lifecycle, account status, review, pricing and capabilities must be checked against official docs and actual developer accounts. Maintain dated capability record and contract tests. Unsupported operations disabled with reason. OAuth state/PKCE where supported, exact redirect allowlist, TLS, encrypted token vault, refresh locking and revoke/disconnect. Never log credentials. Asset URLs served only from controlled delivery with sufficient provider access window and no sensitive content. Reconcile asynchronous upload/container status and remote publication IDs.
## Meta advertising
Use Meta Marketing API, not UI automation. Confirm business portfolio, ad account ownership/currency/payment method, approved Page and Instagram identities, access tier and applicable ads_management/ads_read/business permissions. Obtain app review/business verification where required, especially SaaS. Verify current objectives, optimization goals, destinations, placements, special categories, creative eligibility, targeting restrictions, minimum budget, account settings and review process. Support two workflows: existing eligible post creative and new ad creative. Map local campaign → ad set → ad/creative; choose budget level according to provider support, reject conflicting budgets. Build paused objects first after authorization, reconcile each remote ID, then explicit activation after budget approval. Start and end schedule uses ad account timezone semantics; Meta review can delay delivery. Record configured budget, amount spent, remaining reservation, currency, latest sync and local/remote states. No guaranteed exact spend cap during provider outage or reporting lag. Use eligible lifetime/account spend controls plus conservative reservations and alerts, no unsupported claim of hard stop. Fail closed on stale spend data, config mismatch or unauthorized account. Pause requests retried safely and verified remotely; escalate if unavailable. AI recommends tests, audiences, budgets and creative, never autonomously expands target or spend in pilot. Never target sensitive personal attributes or use unapproved customer lists; require consent/legal review for tracking and retargeting.
## Measurement and official verification references
UTM source=platform, medium=organic_social or paid_social, campaign=stable campaign slug, content=variant ID. Verify on destinations; avoid sensitive data in URL. GA or approved web analytics optional; Meta Pixel/CAPI subject to consent, policy and website owner approval. Deduplicate browser/server conversion by event ID when supported. Use attribution windows and source labeling; distinguish clicks, sessions and conversions, organic vs paid, unique vs summed reach; ROAS only with aligned attributed revenue/spend/currency, divide-by-zero N/A. Store aggregates, not unnecessary personal data. Verify provider docs: https://developers.facebook.com/docs/marketing-apis/ ; https://developers.facebook.com/docs/instagram-platform/ ; https://learn.microsoft.com/en-us/linkedin/ ; https://docs.x.com/ . These are starting references, not verification of live access, price or current scopes. Maintain dated docs/integration-readiness.md.
